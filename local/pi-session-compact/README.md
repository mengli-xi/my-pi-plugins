# pi-session-compact

Stock Pi 1.5 whole-session compaction with ordinary Markdown handoffs and complete cumulative user text. This source-only extension loads TypeScript directly; no build output or Pi private seam. It must be the profile's only `session_before_compact` owner. Magic Context is not migrated or required; neither installation nor tests read its package, configuration or database.

Main and small use prompt version 9. The model describes the current task and effective requirements, completed work and key conclusions, current work and unresolved questions, and next steps. Heading names, ordering and optional sections are guidance. Newer corrections override earlier requirements; important findings, failed approaches and operational handles belong next to the relevant work. Unconfirmed facts remain alongside those items. The model does not produce the user-message appendix or file inventory. There is no output schema, citation table, citation verification, dedicated submission tool, separate uncertainties section, memory-candidate extraction or summary clipping.

Main uses a confirmed effective request capture when available, preserving its exact prefix for cache reuse. For an explicitly allowed absence reason (including immediately after resuming), it rebuilds a main-model request from the current public system prompt, active tool declarations and public branch projection, followed by the same summary instruction. Rebuilding respects compactions and context edits; request-only extension transforms cannot be recovered, so it is not an exact replay or cache-hit claim. It uses a full estimate for window admission, falling back to small when that request does not fit. Incomplete prefixes and captured tool/fingerprint mismatches keep their existing failure paths. Run logs record `outputs.main.prefix` (`source: capture|rebuilt` and `reason`); rebuilt requests also retain `prefixCapture` with the missing capture's store `reason` and `generation` (`null` when no lease exists). `/compaction show` displays the source and reason. No new Main request is required before compaction after resume.

Main preserves the proven `pi-session-runtime` effective system/tools/history prefix and appends instructions, current background materials and focus. An unavailable/unsafe prefix or insufficient input capacity routes the same slot to small. Small uses the frozen public projection, including the previous summary exactly once, custom messages, branch summaries and context edits. Internal chunk IDs/ranges never become model-facing citation annotations. Single-pass planning, group/chunk fitting and synthesis admission all estimate their actual constructed model messages with Pi’s estimator. Large inputs split by complete turn/tool group where possible, and by contiguous Unicode text ranges when necessary. Each chunk writes ordinary temporary prose and synthesis combines it; no middle source range is silently discarded. An overflowing synthesis uses native fallback.

Complete nonempty visible text is usable, including complete prose with unexpected headings and unparseable legacy JSON. Known legacy JSON/whole JSON fences and old `submit_compaction` arguments are read as work prose when possible, omitting old bookkeeping/citation/candidate fields. Returned tools are logged and never executed; visible text takes precedence. Business-tool-only replies are unusable. Blank replies, incomplete streams, `length` stops and Pi-classified transient errors share **one additional attempt per planned request**. Successful chunks are retained; synthesis has its own single allowance. No critic, repair model or hidden repair requests exist. Shadows remain single-attempt. Native uses Pi's own retry policy. User cancellation and session/tree changes never retry, fall back or commit stale output.

`compaction.details.userQuotations` is `{version:1, items:[{kind:"user"|"qa", text:string}]}`. It stores complete text in chronological order, without source IDs or text deduplication. Each compaction appends only user inputs newly removed before its final `firstKeptEntryId`, including the old retained tail now removed. Still-retained inputs stay out of the appendix. Multipart text joins in part order; code, logs, large pastes and whitespace remain intact. Messages under the single all-user-messages heading are separated only by `---`, without repeated user labels; QA text keeps its question/answer fields. No paste placeholders, `key_points` switch or text-length cap exists. Non-text attachments stay in original session history; their binary contents are not represented as user text.

Goal's existing explicit `<!-- pi-goal-continuation:… -->` and `<!-- pi-goal-prompt:… -->` protocol markers identify program prompts. `custom_message` notifications are excluded by entry type even when public conversion gives them user role. All other user-role messages remain eligible, including unknown legacy extension producers. No natural-language prefix matching, live input-origin sidecar or changes to other packages are used. `ask_user_question` answers require an exact tool-call/question pair and current structured answer metadata; answers, selections, user notes and discussion/explanation controls are retained. Earlier answers in an explicitly cancelled questionnaire are labelled as cancelled and do not assert authorization. Ordinary tool output is excluded. Explicit QA context edits use current projected text instead of old answer metadata.

Normal custom compactions inherit the current ancestry's compatible array. Forks and `/tree` use their own branch rather than a global cached array. Legacy/missing arrays, native interleaving, backward cuts and subsequent `context_edit` cause reconstruction from original branch entries with public edit semantics. Deleted/replaced text is not resurrected in the quotation array. No model-written user list is parsed to reconstruct history. Broken ancestry, missing retained boundaries and corrupt accumulated arrays cancel compaction. The plugin's native fallback reconstructs the same array at the **native result's actual cut**. Native keeps its own file appendix; a second inventory is never appended.

Custom results append cumulative `<read-files>` and `<modified-files>` lists. Builtin `read`, `write` and `edit` path arguments and codemode nested calls count as observations, not proof of tool success. Paths deduplicate after lexical normalization against the session cwd: paths inside cwd use relative spelling and outside paths stay absolute; no filesystem lookup is required. Modifications take precedence over reads, including inherited inventory aliases. Original branch calls before the cut are rebuilt with current context edits applied. Revoked cached paths with editable originals disappear; cache-only paths without recoverable original calls remain separately labelled `legacyFileTracking`, rather than being merged into the verified lists. There is no 200-path eviction or summary-percentage quota. Legacy omission counts remain diagnostic when present; missing historical paths are never invented.

压缩恢复通过开放的同步事件 `pi-session-compact:collect-recovery-v1` 收集。请求为 `{version:1,sessionId,operationId,restoreSkills,branchEntries,reply}`。任意插件可在 emit 栈上回复 `{owner,customType,identity,content,order?,covers?}`；`owner` 为自己注册的非空身份，`identity` 由 owner 解释，`order` 是有限数字、升序排列，同序按 owner 字节排序，省略时为 100。Compact 自己的提示使用 order 0，Todo 为 20，Subagents 为 40；没有必答方。`covers` 可声明此次内容覆盖的历史 customType，默认只覆盖回复的 customType。迟到回复被忽略。失败、无效回复或历史标签无人覆盖时，只在恢复正文注明未恢复，不取消压缩、不留下阻断后续请求的状态。这里只看公开 entry 标签和本协议的标记，不解析其他插件的私有 data/details。参与方自行验证和渲染自己的规则、待办、进程及任务状态；收集不启动 service 或 child。

Compact 在生成前和采用 custom/native 结果后各收集一次；后者的同一份快照用于正文、details 与容量核算。恢复附录放在交接、完整用户原话和文件清单之后，标题为 `## 压缩恢复内容`，各项为 `### <owner> (<customType>)` 后跟原文。

持久化 `compaction.details.version` 保持 2，`recovery:{version:1,items:[{owner,customType,identity,order?,covers?}]}` 只存身份，正文仅在 summary。旧版无 order 的回复和 version 1 recovery/details 标记仍可读，旧记录不重写；Compact 自己旧 `restoreSkills` 引用只用于未恢复提示，不要求旧技能插件应答，也不发旧修复请求。Todo/Subagents 按自己 owner/customType 的 recovery 标记抑制重复独立恢复；无标记时保留其独立公开 `session_compact` 路径。

可选技能材料通过开放的同步事件 `pi-session-compact:collect-materials-v1` 提供：请求 `{version:1,sessionId,branchEntries,reply}`，回复 `{owner,skills:[{sourceEntryId,name,path,contents}]}`。owner 自行选择实际加载的版本，Compact 计算 contentHash；同路径取最后一次有效贡献。无人提供时 skills 为空，不读取旧技能插件私有 binding 结构。`restoreSkills` 仅把这些公开引用传给恢复参与方，不意味着必须恢复。

项目记忆只消费 `cc-memory:request:materials-v1` 的公开数据，不打开记忆目录或文件。请求 `{version:1,sessionId,context,reply}`，提供方在 emit 栈上 `reply(payload或Promise<payload>)`；payload 为 `{version:1,sessionId,memory:[{path,contents}],known:[{kind,statement}]}`。全部已登记的异步回复共用 5 秒等待上限；超时记 known 并继续压缩，已完成回复仍保留。取消压缩立即中止收集并清理 timer/listener，不生成或提交结果。忽略迟到/其他 session 回复，重新计算内容 hash。路径仅作来源标识，不要求目录布局。没有提供方时正常压缩，记忆材料为空；读失败由 owner 提供说明。选择与读取规则由 [pi-cc-memory](../pi-cc-memory/README.md) 定义。

Capacity checks cover the entire restored context, not a summary quota: system/tools, handoff, cumulative quotations, unchanged legal tail, full skills, recovery notice, file lists, known request-only owner injections and configured output reserve. 请求层额外注入按实际捕获前缀与公开 session projection 的内容差额保守计费；不再通过技能插件私有 binding 证明某条注入可排除。Native fallback recomputes this overhead at its own final cut. Fixed material that cannot fit cancels before generation. If the generated body makes restoration too large, native may run once and must pass the same gate; otherwise cancel and preserve history. Cuts do not advance to squeeze a summary into a quota. Each business request is checked again in public `context_with_system`, after all `context` owners have projected their actual content. Later additions can block that request; an already committed compaction is reported as committed, not claimed to have been rolled back. Original session entries remain available. Message sizing uses stock Pi 1.5 `estimateTokens`: each image costs its fixed 1,200-token estimate regardless of base64 length; tool results count content, not their session metadata/details. System sections and tool declarations follow the same Pi estimator. A confirmed same-model effective request capture, paired with its first assistant response, supplies the measured membership proof. The saved bound contains only fingerprints and multiplicities from that actual request; an assistant usage without capture cannot cap the raw session tail. Later inputs and the response itself use separate Pi estimates. Edits/compactions/model changes invalidate association; resume can reuse the operation log’s versioned proof, while legacy logs safely fall back to Pi estimates. Committed proofs live separately from first-request usage accounting; tree navigation selects only the active branch’s exact compaction and never borrows another session or operation’s proof. Request-stage matching keeps new/edited/duplicate owner content and all new summary/recovery material outside that bound. Estimates remain estimates, not tokenizer truth; base64 transport-byte admission remains separate from token admission. Future handlers that modify content after this hook require joint integration verification.

The one-paragraph recovery notice says to follow the latest effective requirements, treat quotations as history with newer corrections taking precedence, avoid repeating completed work and use owner state/actual notifications for running work. Processes/Subagents keep their existing standalone fallback and completion/mailbox behavior; collection changes only the compaction snapshot carrier. Goal behavior is unchanged.

`summaryTokens` is a retired compatibility setting. Reading it emits an explicit Chinese disabled notice; its value never controls acceptance, rendering, cuts or window minimum. `outputTokens` still limits provider generation and contributes to physical admission/timing. Old retry settings are read for compatibility, while the per-request custom retry ceiling is always one; network enablement and backoff follow the configured/Pi policy.

- `/compact [instructions]` retains Pi's native parser.
- `/compaction now [auto|main|small] [focus…]` overrides one operation only; omitted mode follows configuration.
- `/compaction window [<tokens>|off]` sets an ancestry-local effective window without writing configuration. Sizes accept `262k`, `262144`, `1m` and decimals; `k=1000`. The value cannot exceed the real model window and must hold known system/tools, current summary, configured output reserve and existing kept-tail/margins. The command reports current handoff, quotations, tail and recovery/notification sizes. Settled usage strictly over 90% calls public `compact()` once; an unsuccessful/over-threshold result warns once until usage falls below or another compaction appears. Existing keep-recent/default settings are unchanged.
- `/compaction show` 显示实际投影摘要、交接/原话/文件/尾部/恢复包大小、采用模式、触发原因、重试、耗时与影子状态。技能显示为“公开材料引用；恢复状态见附录”，不凭其他插件私有消息断言已恢复。旧日志/details 无新字段仍可读；TUI 首次使用时加载只读 UIKit 文本面板，RPC 使用通知；不再显示 citation/quota 诊断。
- `/compaction reserve [write]` retains registry-based 90% threshold auditing. `write` requires the existing confirmation UI, rereads under Pi-compatible `proper-lockfile` locking, backs up original bytes and atomically edits only selected global model token settings. Unknown fields/order and unrelated concurrent edits survive; conflicting compaction/project changes or duplicate ineffective keys abort. Project settings remain unchanged; restart Pi after writes.

Trigger diagnostics do not install a new trigger or a dynamic percentage policy. Logs retain the native event reason and selected model window, record the supplied `preparation.settings.reserveTokens`, and derive the stock Pi condition `tokens > window - reserve` and its first integer trigger. A session-window trigger records its own boundary separately; manual and overflow compactions are not labelled as percentage-triggered. `/compaction show` displays these relationships. They describe the selected model window, not proof of a virtual route's actual window. Without a session window, an unavailable native boundary is diagnosed rather than silently skipped. The 90% mismatch notice accepts both the existing strict-boundary reserve and the one-token adjustment needed for an inclusive integer boundary; this does not infer or enable a dynamic policy. Registry reserve auditing/writes remain explicit token-setting snapshots, not automatic updates for future models or window changes.

Argument completions derive from parser constants and real grammar scaffolds. Unknown inputs return `null`. `window`/`show` output never becomes a model message. CC Style's `statusline:row` displays current-branch `CP` counts/native fallback marker and optional `CT` threshold, and a click opens the same show view. No CC dependency is required to run compaction.

Main/small/auto selection, default shadow-off adoption, input freezing, operation/session fences, failure cooldown, private atomic run logs, queue-aware deadlines and resume reconciliation remain. Shadows never delay or replace adoption and never restore state. Session boundaries, next compaction and abandoned operations cancel them; resume marks interrupted requests without replay. Default custom total timeout is ten active minutes (`0` disables it); validated `provider:activity-v1` queues matching the current session and an active request's provider pause clocks, with a shared thirty-minute union cap. A different provider cannot pause a single-attempt clock or end its queue on progress. The first generation delta closes that provider's current queue window; late `queuedMs` may revise only the past. Missing/malformed/unmatched events never extend deadlines. Native fallback runs outside an exhausted custom total budget. See [provider activity contract](docs/provider-activity.md). Wire/cache attribution remains unknown unless observed.

`smallModel` has no built-in provider or model. Configuration lives at the runtime `getAgentDir()` directory's `pi-session-compact/config.json`. The default `mode: "main"` continues using the current model and unchanged Main/native algorithms. To use a separate model, explicitly set `smallModel: { "provider": "your-provider", "id": "your-model", "effort": "off" }` (`effort` defaults to `off`). When small/auto/shadow or Main fallback needs the frozen-source path without this setting, it uses the current model and current effort, records/notifies that choice and retains native fallback on failure. Explicit configuration is exact: missing models or unsupported effort report the requested identity/error, never silently switch provider or use a faster model. Invalid configuration is diagnosed rather than replaced with a default.

Deadline planning retains the existing generic estimates (2,000 input and 120 output tokens/second, safety factor 3), not internal model tuning or a throughput guarantee. Explicit fresh per-model throughput profiles can improve estimates; their existing staleness and concurrency checks remain. Window/output limits, operation deadlines, per-request deadlines, retry fencing and native admission remain independent safety gates.

`session_search({query,roles?,branch?:"active"|"all",limit?:1..50,cursor?})` and `session_expand({entry_id,part_index?,offset?,limit?})` keep their existing interfaces. Search reads original text with NFC/case-insensitive word AND matching, active ancestry by default, newest matches first and an 8 KiB result limit. Expansion uses exact IDs and Unicode code-point pagination, default 4000/maximum 32 KiB text, and image metadata without base64. Edited originals explicitly identify `contentView:"original"`; hidden thinking and retrieval echoes stay excluded. The in-memory ID/byte-offset index follows append and invalidates cursors on replacement/truncation; no database or transcript archive is created.

Validation:

包内 recovery/material 测试只发送公开协议 DTO；不读取其他插件的私有 binding，也不模拟其注入或恢复实现。

```sh
npm run check
PI_COMPACT_HOST_BINARY=/absolute/path/to/pi-1.5.0 node scripts/check-host.mjs
node --experimental-strip-types scripts/replay-saved.mjs /path/to/copied-inputs /path/to/evidence
```

The host checks require an explicit Pi 1.5.0 executable (stock or the compatible theme-patched build) and use temporary HOME/profile/session, faux responses, real skill/todo owners and zero real model requests. `PI_COMPACT_HOST_ARTIFACTS` saves payload/session/run evidence. Offline replay accepts only explicit copied inputs (`runs/` and `sessions/`), never reads daily agent directories and never imports a network runner. It reconstructs file paths against the copied session header's cwd and verifies recovery with the matching persisted compaction's actual owner appendix/system message and saved request-only accounting. Missing or inconsistent material is reported as `originalCutWindowUnverified`, never as a full recovery pass; summary-output acceptance remains a separate result. Real-model quality/cache/throughput evaluation and full-profile rollout are separate work. `tests/fixtures/eval-real/cells.json` 保留被测试引用的合成交接样本，只验证 legacy prose 提取，不发 provider 请求。

## Usage regression

These manual checks are not claimed by the offline checks above. 协作方为可选；用隔离 profile 验证存在与缺失两种情况，不把旧 post-compaction handler 当成同步收集回复。

- Run `/compaction now main`, then `/compaction show`; repeat with `small`. Check the adopted mode, prefix source, Markdown handoff and complete user quotations. Missing source evidence must be shown as unknown, not an exact replay claim.
- Supply a one-time focus through `/compact`, including an active restriction. It should affect only that operation and must not execute commands from the focus. Read/edited file paths should normalize against the session cwd; active skills, todo and live work should appear once in recovery.
- Set a valid `/compaction window <tokens>`, cross its displayed boundary and settle a run. Check the `session-window` source and one-attempt anti-loop behavior; `window off` returns to native policy. The native reserve relationship is diagnostic, not a promise of automatic dynamic 90% support.
- Resume or navigate to another branch. Committed work must not regenerate, quotations must follow that ancestry, and a new completion must not duplicate restored notifications. Use `session_search`/`session_expand` to check originals; edited originals must identify themselves as original content.
- In a disposable profile, configure an unavailable explicit small model or a recovery package that cannot fit. Expect an explicit diagnostic and the documented native fallback/cancellation, not a silent provider switch or dropped recovery text; retain the original history and restore the test configuration afterward.

Rebuilt Main, small and native fallback materials pass through the mailbox owner's
read-only `filterMailboxMessages` before custom identities become ordinary text.
Cancelled/receipt-GC and recovery-held carriers stay excluded; legitimate fulfilled/live
shared carriers remain. This never runs arbitrary context hooks or producer callbacks,
changes mailbox state, or releases recovery hold. Unverifiable identity/ABI/IO rejects
through the existing compaction failure paths. `pi-session-inject` remains lazy at startup.

Only explicit absence reasons (`no-capture`, `awaiting-provider-capture`,
`native-compaction`, `provider-not-decoratable`) allow Main rebuilding. Structural,
identity and branch failures, including those a Side selection has already recorded
while clearing capture, retain their previous failure path; unknown reasons fail closed.
File inventories parse Pi 1.5 builtin `~`, `@`, file URLs and Unicode-space syntax
before resolving against cwd, and prefix literal relative `~`/`@` names with `./`.
The parser is checked against the public write tool's operations boundary, without
using unexported Pi path helpers or looking up file contents.
Unparseable historical path observations (including malformed file URLs from failed
tool calls) retain their original spelling in a separate identity namespace. They
never merge with resolved paths or cancel compaction because of a parsing error;
direct calls, nested calls and inherited inventories use the same fallback.
